<binding_facts>
These are MEASURED against GAMS 54.1. Do not re-derive them, and do not write a
criterion that contradicts them.

1. **The exact-integer ceiling is `2^53 ≈ 9.007e15`.** Above it, emission fails in two
   distinct ways: `2^96` prints as `7.922816251426434000E+28` (scientific — not
   calldata), and `12345678901234567` prints as `12345678901234568` — **silently off by
   one**. At Q96 magnitude (~7.9e28) the double spacing is `2^44 ≈ 1.759e13`: a 97-bit
   `sqrtPriceX96` retains 53 bits and **its low 44 bits do not exist**.
2. **`$eval 2**96` is wrong by exactly `2^45`** (measured `log2(diff) = 45.0000`).
   `power(2,96)` is exact. Compile-time `$eval` is therefore forbidden for scale constants.
3. **`1e18` IS exact** — `5^18 · 2^18`, odd mantissa `5^18 ≈ 3.8e12 < 2^53`. So is
   `1.0001e18 = 10001 · 10^14` — odd mantissa `10001 · 5^14 = 61045619140625 ≈ 6.1e13 < 2^53`.
   Exactness above `2^53` is a property of the **odd mantissa**, not of the value.
4. **Q96 in a `Variable` is a hard failure, not precision loss:** measured
   `solveStat=10`, `modelStat=13`, `*** SOLVER ERROR`, variables left silently at their
   starting values. Fixed-point magnitudes stay in macros and scalars, never in variables.
5. **A registry row whose command is `make …` uses `expect = nonzero`** — GNU make
   collapses any recipe failure to its own exit status 2. Rows invoking `gams` or
   `python3` directly pin the exact code (`gams` returns 2 on compile error, 3 on abort).
6. **Every new mutant must be OBSERVED to fail before its row is committed.**
   `Scalar broken / 1 /` followed by garbage returns rc=0 — GAMS continues the
   declaration across the line break. A mutant that cannot fail is worse than none.
7. **`abort` accepts identifiers only, never expressions**, in its message argument list.
   The `abort$( … )` *condition* may be an expression. Every guard macro written here
   therefore takes an identifier for anything it displays.

8. **Duplicate declarations — MEASURED on GAMS 54.1, and the earlier `$150` story in
   this plan was wrong three ways.** Probed directly:

   | duplicate | result |
   |---|---|
   | `Scalar Q96; Q96 = power(2,96);` twice | **rc=0. Tolerated. SILENT.** |
   | `Set inventory /assetX, cashY/;` then `Set inventory /X, Y/;` | **rc=2, `**** 194 Symbol redefined - a second data statement for the same symbol`** |

   `$150 Symbolic equations redefined` is a different diagnostic and is not what either
   case produces, and `$onMulti`/`$onMultiR` **do** suppress the `Set` case (which is
   exactly why LINT-04 forbids them). The consequence for this plan is the opposite of
