**2. Write `model/lint/rules.tsv`.** Seven TAB-separated columns:
`id`, `severity`, `kind`, `pattern`, `partner`, `window`, `message`.
`kind` is `forbid` (any matching line is a violation) or `require_within` (a line matching
`pattern` must be followed within `window` lines by a line matching `partner`). `partner` and
`window` are empty for `forbid`. Patterns are Python `re` syntax; use an inline `(?i)` where case
folding is wanted. Content:

```
# GAMS source lint rules. APPEND-ONLY, one rule per line (M7).
# id	severity	kind	pattern	partner	window	message
# kind=forbid: any line matching `pattern` is a violation (partner/window empty).
# kind=require_within: a line matching `pattern` must be followed within `window`
#   lines by a line matching `partner`.
#
# ── GATE-02 ───────────────────────────────────────────────────────────────
LINT-01	error	forbid	(?i)\babort\.noError\b			abort.noError halts execution silently at rc=0 with no status line (GATE-02)
# ── GATE-04 — execute and $call need SEPARATE rules: $onCheckErrorLevel
#    governs $call ONLY, measured (it does not make `execute 'false'` fail).
LINT-02	error	forbid	^[^*#]*\bexecute[ \t]+\S			a failing `execute` returns rc=0; set execute.checkErrorLevel before it (GATE-04)
LINT-03	error	forbid	^\$call(Async)?\b(?!\.checkErrorLevel)			a failing $call returns rc=0; use $call.checkErrorLevel or $onCheckErrorLevel (GATE-04)
LINT-04	error	forbid	(?i)^\$onMulti			$onMulti* silently REPLACES a symbol at rc=0 (GATE-04, REPR-04)
LINT-05	error	forbid	^[^*#]*\bexecError[ \t]*=			assigning execError forges the error state (GATE-04)
```

Note LINT-02 deliberately requires whitespace immediately after `execute`, so `execute_unload`,
`execute_load`, `execute_loadDC` and `execute.checkErrorLevel` are not matched. That is measured:
the current tree has 3 `execute_unload` sites and 0 violations.

**3. Write `model/lint/lint_gams.py`:**

- CLI: `lint_gams.py [--rules FILE] [PATH ...]`. With no PATH, the file set is
  `git ls-files 'model/*.gms' 'model/**/*.gms'` filtered to drop anything under `model/build/` or
  `model/test/_mutants/`. With PATHs given, exactly those files are scanned (this is how the
  mutants are driven).
- Load rules from the TSV: skip blank lines and lines whose first non-space character is `#`;
  require exactly 7 TAB-separated fields; exit 2 with a clear message on a malformed line, an
  unknown `kind`, a duplicate `id`, an uncompilable regex, or **an empty rule file** — an empty
  rule table is a false pass.
- `forbid`: report every line matching `pattern`.
- `require_within`: for every line matching `pattern`, join the following `window` lines and
  report if `partner` does not match that joined text.
- Report as `<path>:<lineno>: <id> <severity> <message>` followed by the offending source line.
- Print `lint-gams: F files, R rules, V violations` and exit 1 if any `error`-severity violation
  exists, else 0. `warn` severity prints but does not fail.
- Exit 2 if the file set is empty — a lint that scanned nothing must not report green.
- No `grep` subprocess anywhere; pattern matching is in-process, and the target's own pass/fail is
  its exit code.
